MILLENNIUM PLATFORM UPGRADE - PLANNING NOTES
============================================
Health System: UCSF Medical Center
Current Version: Millennium 2022.11
Target Version: Millennium 2023.5 (Oracle Health rebrand)
Planning Lead: Jennifer Martinez, Clinical Informatics Director
Date: July 18, 2024

UPGRADE OVERVIEW
----------------

Release: Millennium 2023.5 (Oracle Health)
Release Date: October 2023
Our Target Go-Live: February 2025 (6 months away)

Why Upgrade:
1. Current version out of support in March 2025
2. New features needed for regulatory compliance (eCQMs, TEFCA)
3. Performance improvements (20-30% faster according to Oracle)
4. Security patches and vulnerability fixes
5. Oracle integration features (cloud migration path)

Scale of Effort: LARGE
- Estimated hours: 4,500 hours (internal team + Oracle consultants)
- Cost: $850K (consulting + testing + overtime + downtime)
- Timeline: 8 months (Aug 2024 - Feb 2025)
- Risk: HIGH (core clinical system, 24/7 operations)

KEY FEATURES IN 2023.5
----------------------

1. PowerChart Enhancements
   - New medication reconciliation workflow (addresses current pain point!)
   - Improved mobile responsiveness on tablets
   - Customizable preference sets per provider
   - Better integration with CPOE for order modifications

2. Population Health & eCQMs
   - Enhanced quality measure reporting (required for CMS)
   - FHIR R4 support (current version only supports R3)
   - Bulk data export API for payer data sharing
   - This is main driver for upgrade - compliance deadline is June 2025

3. Security & Infrastructure
   - TLS 1.3 support (current 1.2 will be deprecated)
   - Enhanced audit logging for HIPAA
   - Database performance optimizations
   - Support for Oracle Cloud Infrastructure (future migration)

4. Patient Portal (HealtheLife)
   - Modernized UI (finally! Current portal looks dated)
   - Mobile app improvements
   - Video visit integration
   - Patient-generated health data ingestion

5. Interoperability
   - TEFCA QHIN participation support
   - Carequality integration enhancements
   - CommonWell link updates
   - Prior auth automation workflows

TECHNICAL CHANGES
-----------------

Database:
- Oracle DB upgrade: 19c → 21c (required)
- Database size expected to grow 15-20% (add 800GB storage)
- New indexes will be created (performance improvement but longer upgrade window)

Application Servers:
- .NET Framework: 4.8 → .NET 6.0 (major change)
- Windows Server: 2019 → 2022
- IIS: 10 → 10.5
- Need to rebuild all custom integrations that use .NET

Infrastructure Requirements:
- 6 additional application servers for performance (CAPEX: $180K)
- Storage expansion (CAPEX: $95K)
- Network bandwidth upgrades for new FHIR APIs (CAPEX: $40K)
- Total infrastructure cost: $315K (not in original budget - need CFO approval)

Custom Code Impact:
- 47 custom scripts and integrations identified
- 23 will break in new version (breaking changes in APIs)
- 12 can be replaced by native features (opportunity to reduce tech debt!)
- 12 need to be rewritten

Integration Testing Scope:
- Epic integration (for research patients): CRITICAL - must test thoroughly
- Lab interfaces (LabCorp, Quest): HIGH PRIORITY
- Radiology (PACS): HIGH PRIORITY
- Pharmacy (Omnicell, Pyxis): CRITICAL
- Revenue cycle (Epic Resolute): HIGH PRIORITY
- Single sign-on (Okta): CRITICAL
- Reporting tools (Tableau): MEDIUM
- Quality registries (AHA, STS, others): MEDIUM

RISKS & CONCERNS
----------------

1. DOWNTIME DURATION - HIGH RISK
   Planned: 18 hours
   Risk: Database upgrade could take longer than estimated
   Impact: Clinical operations severely impacted, potential patient safety issues
   Mitigation:
   - Dry run upgrade in test environment to validate timing
   - Downtime procedures for paper-based workflows
   - Rollback plan if upgrade exceeds 24 hours
   - Schedule during lowest census period (February)

2. CUSTOM CODE BREAKS - HIGH RISK
   23 integrations will break, 12 need rewrites
   Impact: Workflows disrupted, staff workarounds, potential data loss
   Mitigation:
   - Start custom code work early (October)
   - Parallel testing in TEST environment
   - Manual workarounds documented and tested
   - Extended hypercare support for integration issues

3. USER ADOPTION OF NEW WORKFLOWS - MEDIUM RISK
   Med rec workflow changing significantly
   Impact: Productivity decrease, medication errors if done incorrectly
   Mitigation:
   - Early physician champion engagement
   - Hands-on training (not just videos)
   - Super-users embedded in clinical areas during go-live
   - Quick reference guides at workstations

4. INFRASTRUCTURE COST OVERRUNS - MEDIUM RISK
   $315K not in budget
   Impact: Project delay if funding not approved
   Mitigation:
   - Business case submitted to CFO (July 15)
   - Alternative: Phased infrastructure upgrades (riskier)
   - Cost avoidance: Oracle Cloud migration postponed saves $200K this year

5. EPIC INTEGRATION FAILURE - CRITICAL RISK
   Small number of research patients use both Cerner and Epic
   Integration is fragile and poorly documented
   Impact: Research disruption, patient safety concern if data not synced
   Mitigation:
   - Dedicated testing window with Epic team
   - Epic integration specialist from Oracle assigned
   - Contingency: Manual data entry process during outage

6. VENDOR DELAYS - MEDIUM RISK
   Oracle (Cerner) has history of delayed support responses
   Impact: Testing delays, go-live postponement
   Mitigation:
   - Premium support contract ($45K) for dedicated engineer
   - Weekly check-ins with Oracle project manager
   - Escalation path to Oracle executive sponsor

TECHNICAL CHALLENGES
--------------------

1. Epic Clinical Notes Extraction
   Problem: Our initial approach was pulling all progress notes in real-time via Epic API
   Impact: Epic application servers showing 15-20% CPU increase during business hours
   Epic TAM (Karen) flagged this as unsustainable

   Solution in progress:
   - Switch to overnight batch extraction
   - Only pull notes modified in last 24 hours
   - Use Epic's bulk FHIR export instead of individual API calls
   - Health Catalyst engineer (Priya) building revised ETL pipeline

   Timeline: 2 weeks to redeploy, test, and validate

   Risk: This delays our NLP pilot for patient complexity scoring by 3-4 weeks

2. Data Volume Larger Than Expected
   Estimate at kickoff: 750GB total data warehouse size
   Actual: Already at 1.2TB and still loading historical data

   Impact: Need to provision additional storage faster than planned
   Cost: Extra $18K for storage (not in original budget)

   Root cause: Underestimated granularity of lab data (getting individual test results, not just summary panels)

   Decision: Proceed with additional storage - Amanda approved via email 8/13

3. User Authentication Integration
   Problem: Initial SSO config only working for @clevelandclinic.org emails
   Many of our analysts use @ccf.org domain - not authenticating

   Health Catalyst Support ticket #47291 - escalated to engineering
   Workaround: Manually provisioning accounts for @ccf.org users
   Permanent fix ETA: August 23

LESSONS LEARNED SO FAR
----------------------

What Went Well:
- Health Catalyst team is responsive and knowledgeable
- Project governance structure (weekly standups, biweekly steering) keeps us aligned
- Data quality focus from day 1 paid off - few surprises
- Executive sponsorship from Amanda has been crucial for issue resolution

What Could Be Better:
- Should have done more detailed data volume analysis upfront
- Need better coordination with Epic team (they felt blindsided by API load)
- Training should start earlier - users want hands-on time before go-live
- Budget should include 15-20% contingency for infrastructure surprises

Recommendations for Future Projects:
1. Always pressure-test vendor's infrastructure sizing estimates
2. Involve all IT stakeholders (Epic, network, security) in kickoff
3. Plan for training to happen 4-6 weeks before go-live, not 1-2 weeks
4. Build in budget buffer for unplanned technical needs
